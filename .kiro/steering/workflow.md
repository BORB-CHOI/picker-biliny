# 워크플로우 규칙

## 질문 우선 원칙

- 디자인 의도, 애니메이션 방향, 레이아웃 구조가 불명확하면 추측하지 말고 반드시 질문한다
- 특히 다음 상황에서는 구현 전에 확인:
  - Figma 디자인에서 여러 해석이 가능할 때
  - 애니메이션 타이밍, 이징, 방향이 명시되지 않았을 때
  - 기존 코드를 제거하거나 크게 변경해야 할 때
  - 사용자가 "~처럼", "~느낌으로" 등 감각적 표현을 사용했을 때
- 잘못 구현해서 되돌리는 비용 > 질문 한 번 하는 비용

## 변경 전 확인

- 기존에 동작하는 코드를 제거/변경할 때는 사용자에게 의도를 먼저 확인
- "수정하면 될 것 같아" ≠ "제거해줘" — 문맥을 정확히 파악

## 스킬 라우팅

사용자의 요청이 아래 패턴에 해당하면 해당 스킬을 먼저 활성화한다:
- 제품 아이디어, 브레인스토밍 → office-hours
- 구현 계획 → plan
- 코드 리뷰, diff 확인 → review
- 디자인/UI 리뷰 → design-review
- QA, 테스트, 버그 찾기 → qa
- 배포, PR, 쉽 → ship
- 전체 리뷰 파이프라인 → autoplan
