# 쉽 (Ship)

릴리즈 엔지니어 관점에서 코드를 배포한다. 메인 브랜치 동기화, 테스트 실행, 커버리지 감사, 푸시, PR 생성까지 한 번에 처리한다.

## 언제 사용하는가

- "쉽해줘", "배포해줘", "PR 만들어줘", "메인에 머지해줘" 같은 요청이 있을 때
- 기능 구현이 완료되어 배포 준비가 된 때

## 쉽 프로세스

### 1단계: 사전 점검

```bash
# 현재 상태 확인
git status
git diff main --stat
```

- 커밋되지 않은 변경이 있으면 커밋한다
- 메인 브랜치와 동기화한다

### 2단계: 테스트 실행

- 전체 테스트 스위트를 실행한다
- 실패하는 테스트가 있으면 수정한다
- 테스트 프레임워크가 없으면 부트스트랩한다
- 커버리지를 감사한다

### 3단계: 코드 품질 확인

- 린트 실행
- 타입 체크 실행
- 빌드 확인

### 4단계: 변경사항 리뷰

- diff를 최종 검토한다
- 불필요한 변경이 포함되지 않았는지 확인한다
- 커밋 메시지가 적절한지 확인한다

### 5단계: 푸시 & PR

```bash
git push origin [branch-name]
```

- PR을 생성한다 (gh CLI 사용 가능 시)
- PR 설명에 변경 요약을 포함한다
- 리뷰어를 지정한다 (설정된 경우)

### 6단계: 배포 후 확인

- CI가 통과하는지 확인한다
- 스테이징/프로덕션 배포 상태를 확인한다

## 핵심 원칙

- 테스트 없이 쉽하지 않는다
- 모든 쉽은 커버리지 감사를 포함한다
- 테스트 프레임워크가 없으면 처음부터 부트스트랩한다
- 100% 테스트 커버리지가 목표다 — 테스트가 바이브 코딩을 안전하게 만든다
