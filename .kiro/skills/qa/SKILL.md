# QA (품질 보증)

QA 리드 관점에서 앱을 테스트한다. 버그를 찾고, 수정하고, 수정이 맞는지 재검증한다. 모든 수정에 대해 회귀 테스트를 자동 생성한다.

## 언제 사용하는가

- "QA 해줘", "테스트해줘", "버그 찾아줘" 같은 요청이 있을 때
- 스테이징 URL이나 로컬 서버를 테스트할 때
- 배포 전 최종 점검이 필요할 때

## QA 프로세스

### 1단계: 테스트 범위 파악

- 변경된 파일과 기능을 파악한다
- 영향받는 사용자 플로우를 식별한다
- 테스트 우선순위를 정한다 (크리티컬 패스 먼저)

### 2단계: 기능 테스트

각 기능에 대해:
- 해피 패스 테스트
- 에러 패스 테스트
- 엣지 케이스 테스트
- 경계값 테스트

### 3단계: 크로스 브라우저/디바이스

- 반응형 레이아웃 확인
- 터치 인터랙션 확인
- 키보드 네비게이션 확인

### 4단계: 성능 체크

- 페이지 로드 시간
- 큰 데이터셋에서의 동작
- 메모리 누수 징후

### 5단계: 버그 수정 사이클

버그를 발견하면:
1. 버그를 정확히 기술한다 (재현 단계, 예상 결과, 실제 결과)
2. 원인을 분석한다
3. 최소한의 수정을 적용한다 (아토믹 커밋)
4. 수정이 맞는지 재검증한다
5. 회귀 테스트를 생성한다

## 핵심 원칙

- 버그를 찾으면 반드시 수정하고 재검증한다
- 모든 수정에 회귀 테스트를 추가한다
- "동작한다"가 아니라 "올바르게 동작한다"를 확인한다
- 사용자가 실제로 경험할 시나리오를 테스트한다
