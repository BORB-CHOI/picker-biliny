# 디자인 리뷰 (Design Review)

시니어 디자이너 관점에서 계획 또는 구현물의 UI/UX를 심층 리뷰한다. 각 디자인 차원을 0-10으로 평가하고, 10점이 어떤 모습인지 설명한 뒤, 거기에 도달하기 위한 수정을 제안한다.

## 언제 사용하는가

- UI/UX 변경이 포함된 계획을 리뷰할 때
- 구현된 UI의 품질을 점검할 때
- "디자인 리뷰 해줘", "UI 괜찮아?" 같은 요청이 있을 때

## 평가 차원 (각 0-10)

### 1. 정보 위계
- 사용자가 가장 먼저, 두 번째로, 세 번째로 보는 것은?
- 시각적 우선순위가 비즈니스 우선순위와 일치하는가?

### 2. 인터랙션 상태 커버리지
```
기능 | 로딩 | 빈 상태 | 에러 | 성공 | 부분
```
- 모든 상태가 디자인되어 있는가?
- 빈 상태가 기능인가, 방치인가?

### 3. 사용자 여정 일관성
- 감정적 흐름이 자연스러운가?
- 단계 간 전환이 매끄러운가?

### 4. AI 슬롭 감지
- 제네릭한 UI 패턴을 그대로 쓰고 있지 않은가?
- 이 제품만의 개성이 있는가?

### 5. 디자인 시스템 정합성
- DESIGN.md나 기존 디자인 시스템과 일치하는가?
- 새로운 패턴이 기존 패턴과 충돌하지 않는가?

### 6. 반응형 의도
- 모바일이 의도적으로 설계되었는가, 후순위인가?
- 터치 타겟이 충분한가? (최소 44px)

### 7. 접근성 기본
- 키보드 네비게이션이 가능한가?
- 스크린 리더 호환성은?
- 색상 대비는 충분한가?

### 8. 엣지 케이스 대응
- 이름이 47자면? 결과가 0개면? 네트워크 실패 시?
- 첫 사용자 vs 파워 유저 경험 차이는?

## 리뷰 프로세스

1. 각 차원을 0-10으로 평가한다
2. 10점이 어떤 모습인지 구체적으로 설명한다
3. 현재 점수에서 10점까지의 갭을 분석한다
4. 수정 제안을 우선순위와 함께 제시한다
5. 디자인 선택이 필요한 부분은 사용자에게 질문한다

## 출력 형식

```
디자인 리뷰 결과

```

## 핵심 원칙

- "충분히 괜찮다"는 목표가 아니다. 10점을 목표로 한다.
- 모든 인터페이스 결정은 사용자 신뢰를 쌓거나 깎는다.
- UI 요소가 자기 픽셀을 정당화하지 못하면 제거한다.
- 기능 과잉은 기능 부족보다 빠르게 제품을 죽인다.
