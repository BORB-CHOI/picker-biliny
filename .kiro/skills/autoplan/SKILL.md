# 오토플랜 (Autoplan)

한 번의 명령으로 전체 리뷰 파이프라인을 실행한다. CEO 리뷰 → 디자인 리뷰 → 엔지니어링 리뷰를 자동으로 순서대로 실행하고, 사용자 판단이 필요한 결정만 표면화한다.

## 언제 사용하는가

- 새 기능의 계획을 전체적으로 리뷰하고 싶을 때
- "전체 리뷰 돌려줘", "오토플랜" 같은 요청이 있을 때
- 계획의 완성도를 한 번에 검증하고 싶을 때

## 파이프라인 순서

### 1. CEO 리뷰 (스코프 & 전략)

- 이게 맞는 문제인가?
- 스코프가 적절한가? (확장/유지/축소)
- 12개월 후 이상적 상태와의 갭은?
- 대안 접근법은?

4가지 모드:
- **스코프 확장**: 더 크게 생각한다. 10배 버전을 제안한다.
- **선택적 확장**: 현재 스코프를 유지하되, 추가 기회를 개별적으로 제시한다.
- **스코프 유지**: 현재 스코프를 방탄으로 만든다.
- **스코프 축소**: 핵심만 남기고 나머지를 잘라낸다.

### 2. 디자인 리뷰 (UI가 있는 경우)

- 정보 위계, 인터랙션 상태, 접근성
- 각 차원 0-10 평가
- AI 슬롭 감지
- 반응형 의도 확인

### 3. 엔지니어링 리뷰

- 아키텍처 — 의존성 그래프, 스케일링 특성
- 에러 맵 — 모든 실패 경로 매핑
- 보안 — 공격 표면, 입력 검증, 인가
- 데이터 흐름 — 해피 패스 + 섀도우 패스 (nil, empty, error)
- 테스트 — 새 코드패스마다 테스트 존재 여부
- 성능 — N+1, 메모리, 인덱스
- 관측성 — 로깅, 메트릭, 알림
- 배포 — 마이그레이션 안전성, 피처 플래그, 롤백

### 4. 자동 감지

- UI 스코프가 있으면 디자인 리뷰를 포함한다
- 백엔드만이면 디자인 리뷰를 건너뛴다
- 버그 수정이면 스코프 유지 모드를 기본으로 한다
- 새 기능이면 선택적 확장을 기본으로 한다

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

판정: 엔지니어링 리뷰 통과 — 구현 준비 완료
```

## 핵심 원칙

- 사용자 판단이 필요한 결정만 표면화한다
- 명백한 문제는 자동으로 해결한다
- 각 리뷰 단계의 결과가 다음 단계에 반영된다
- 모든 리뷰 섹션을 건너뛰지 않는다 — 발견사항이 없으면 "이슈 없음"이라고 명시한다
